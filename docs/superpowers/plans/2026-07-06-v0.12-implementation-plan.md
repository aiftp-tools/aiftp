# aiftp v0.12 Implementation Plan — サイト台帳（fleet）

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **実装体制**: Codex が実装 + test pass まで担当、commit は Claude が代行（hybrid）。セキュリティ密度の高い F3（fail-closed 照合）・F4（Keychain 命名）は Codex 独立レビュー必須。

**Goal:** 複数サイトを預かる運用者（まず作者本人、次に研修受講者・制作会社）のための管理レイヤーを追加する。本人ドッグフードで判明した3痛点（P1 反復 init / P2 宛先不安 / P3 資格情報散在）を解消し、v0.13 Desktop 拡張・研修商品の前提部品を用意する。

**Architecture:**
- **F1 サイト台帳**: `packages/core/src/sites/registry.ts` に `~/.aiftp/sites.toml`（ポインタのみ・秘密情報なし）の read/write と、各プロジェクトの `.aiftp.toml` + `.aiftp/log.jsonl` + Keychain presence をライブ合成する解決層を新設。CLI `aiftp sites` 系、MCP `aiftp_sites_list`（REDACTED）を追加。
- **F2 設定継承**: `packages/cli/src/init-flow.ts` に `--from <site|path>` 経路を追加。既存 `.aiftp.toml` の非接続セクション（safety/backup/connection/encoding/quirks/walk/preflight/exclude + server_kind/protocol/port）をプリロードし、質問を差分のみに縮約。
- **F3 宛先宣言**: push/rollback の confirm 直前に宛先バナーを描画。MCP `aiftp_push_prepare` / `aiftp_rollback_prepare` の応答に `destination` ブロックを追加し、`aiftp_push_prepare` に任意 `expected_site` の fail-closed 照合を追加。
- **F4 Keychain 命名**: init / `init --from` のデフォルト `keychain_service` を `aiftp:<site>-<profile>` に変更。doctor に衝突 warn を追加。既存 config は明示値を持つため無変更（migration 不要）。
- **v0.11.1 相乗り**: smoke.yml の npm レジストリ待ち、WP テンプレの debug.log 共通 exclude、preflight runtime 接続。

**Tech Stack:**
- TypeScript / Node.js 22+ / pnpm 10 / vitest (TDD, 80%+) / biome
- 既存依存のみ（新規依存なし）。`@iarna/toml` で sites.toml を read/write。`os.homedir()` でホーム解決。

**Spec:** `aiftp/docs/superpowers/specs/2026-07-06-v0.12-sites-fleet-design.md`（**Approved** 2026-07-06、OQ 3点決定済み）

**Branch:** `claude/v0.12-sites-fleet` → PR 経由で main へ（main 直 push しない）

**Ship target:** 未定（研修商品ロードマップに合わせ plan 承認後に設定）

## Non-negotiable 不変条件（全タスク共通）

- 台帳は**ポインタのみ**（path/label/profile 名）。host/user/secret/remote_root を書かない
- MCP は REDACTED（host/user/keychain_service/remote_root を絶対返さない。`aiftp_profile_list` と同方針）
- MCP から台帳を**書き込むツールは提供しない**（v0.12 は read-only。書き込みは CLI `sites add/remove` と init 末尾のみ）
- prepare→confirm 2段ゲート・暗号化 default ON・hard-exclude・パスワード CLI 引数禁止・ログマスキングは一切緩めない
- `expected_site` 照合は fail-closed（不一致・台帳未登録は拒否）
- schema v2 の破壊的変更なし（すべて追加的）
