# v0.11 Marketing Response Analysis

**Measured at**: 2026-06-07 JST
**Campaign period**: 2026-05-28 to 2026-05-30
**Purpose**: Compare product-led X Pattern A with observation-led X Pattern B, then decide the next communication approach.

## Executive decision

**Pattern A won this test.**

The product-led launch post produced more reach, more engagement, and the only measured outbound link click. The observation-led Pattern B did not validate the original hypothesis that a general AI observation would spread further.

However, neither pattern produced a confirmed public conversion such as a GitHub star, fork, external issue, or clearly attributable install. The result should therefore be treated as a messaging signal, not product-demand validation.

### Interpretation

- The personal experience and concrete product problem worked better than the abstract AI observation.
- The feature-heavy middle of the thread lost readers quickly.
- The final post recovered somewhat because it contained a Zenn preview and actionable commands.
- Pattern B's bridge failed to move readers back to Pattern A: it recorded zero engagements and zero link clicks.
- A separate, concrete troubleshooting post on 2026-06-01 about an Opus 4.8 issue reached **374 impressions**, suggesting that specific problems and open questions currently outperform polished announcements on this account.

## Next communication policy

1. **Keep Pattern A pinned.** It remains the strongest product-facing post and contains the only measured outbound click.
2. **Do not repeat Pattern B as a pure observation post.** Use the AI cross-check theme only when attached to one concrete failure, screenshot, or measurable result.
3. **Prefer one-post case studies over long threads.** Use this structure:
   - concrete pain experienced by a builder
   - one visible before/after or terminal screenshot
   - one command or result
   - one CTA
4. **Test the builder wedge directly.** The next post should focus on the practical moment: “AIでサイトを直した後、FTPソフトを開く作業をなくした”.
5. **Add attribution before the next campaign.** Use campaign-specific UTM links or a redirect URL so X, Zenn, GitHub, and npm movement can be separated.

## Suggested next test

A single before/after post is the best next experiment:

- Hook: manual FTP repetition after AI-generated edits
- Proof: short screen recording or two screenshots showing manual flow vs `aiftp push --dry-run`
- CTA: Zenn article or GitHub, but not both in the main post
- Success threshold: more than 200 impressions, at least 3 link clicks, and one external product action
