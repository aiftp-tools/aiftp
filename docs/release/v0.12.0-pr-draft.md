## PR 本文（案）

### Summary

1 台のマシンで複数のレンタルサーバー / サイトを AI エージェント経由で運用する際の
**資格情報衝突・誤送信・設定重複**を解消する「サイト台帳（site fleet）」機能群（F1〜F4）と、
v0.11 で残課題だった **SFTP ホスト鍵検証（TOFU / CWE-295）** を実装。本人ドッグフード
（glocalworks.co.jp）で顕在化した3痛点への直接対応。

### What's included

- **F1 サイト台帳** — `~/.aiftp/sites.toml`（ポインタのみ・資格情報は Keychain）。`aiftp sites list/add/remove/doctor`、MCP `aiftp_sites_list`（read-only）
- **F2 `init --from`** — 既存サイトから安全セクションのみ継承（host/user/keychain は非継承）
- **F3 宛先バナー + MCP fail-closed** — `⛳ 宛先` 表示 + `expected_site` mismatch を副作用前に拒否
- **F4 keychain 命名** — `aiftp:<site>-<profile>` で複数サイトの資格情報衝突を回避 + doctor collision warn
- **SFTP ホスト鍵 TOFU** — `.aiftp/known_hosts` ピンニング、鍵変化を拒否（MITM 検知）
- **WP テンプレ** — 全4テンプレで `wp-content/debug.log` 除外
- **Fix** — `aiftp sites list --json` が table を返す不具合を修正
- **Fix（Task 14 ドッグフードで発見・修正）** —
  - CLI 本番で SiteRegistry 未配線（宛先バナー・init keychain 命名・台帳登録がスキップ）
  - `init --from` の Protocol select が Enter で TypeError クラッシュ（prompts の initial は数値インデックス必須）
  - MCP 本番で SiteRegistry 未配線（`expected_site` が正宛先でも常時拒否）
