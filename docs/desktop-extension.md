# Claude Desktop 拡張（.mcpb）

- **対応バージョン**: 0.13.0
- **対応 OS**: macOS / Windows
- **ライセンス**: MIT（無料）
- **Node.js 要件（宣言値・未実測）**: 拡張マニフェストは `compatibility.runtimes.node: ">=22.0.0"` を宣言しています。この値は Claude Desktop が実際に同梱する Node.js のバージョンを実機で測った結果ではなく、まだ検証されていない仕様上の要求値です。ご自身の環境で拡張が起動しない場合は、この点を踏まえた上でトラブルシューティング（下記 5 章）を確認してください。

## 1. 導入手順（ターミナル不要）

1. GitHub Release から `aiftp-0.13.0.mcpb` をダウンロードする。
2. ダブルクリックして Claude Desktop に追加する。
3. 設定 UI で以下の項目を入力する: サイト名 / サイトフォルダ / ホスト名 / プロトコル / ユーザー名 / サーバー側フォルダ / パスワード / 合言葉。
4. Claude Desktop を再起動する。

ターミナルを開く必要も、Node.js を別途インストールする必要も、MCP 設定 JSON を手編集する必要もありません。

## 2. 「検証されていない発行元」の警告について

この拡張は**未署名**で配布しています。ダブルクリックした際に、お使いの OS からアプリの発行元を検証できない旨の警告が表示されることがあります。

正式な発行元証明書を取得していないため、警告に表示される正確な文言は macOS / Windows とも実機でまだ確認できていません（実機確認は今後の別作業で行います）。表示された警告の内容が不安な場合は、講師またはプロジェクト管理者に確認してください。

署名しない理由と、それでも安全と言える根拠:

- MIT ライセンス・ソース全公開（<https://github.com/aiftp-tools/aiftp>）。中身はいつでも確認できます。
- 通信はあなたが設定した FTP/FTPS/SFTP サーバとの間だけです。テレメトリ送信は行いません。
- 認証情報（パスワード）は OS のキーチェーンにのみ保存されます。ファイルや設定に平文で書き込まれることはありません。

### 同梱方式についての補足

この拡張は `pnpm deploy` ではなく `pnpm pack` で依存パッケージ（core / mcp / cli）を tarball 化し、`npm install --omit=dev --ignore-scripts` で組み立てています。開発環境で `pnpm deploy` を使うと node_modules 内に自己参照するシンボリックリンクができてしまい、`ENAMETOOLONG` エラーで固まってしまうためです。

また `--ignore-scripts` を付けているため、ビルド時のネイティブモジュールのコンパイルは一切行われません。その結果、SFTP 通信を担う `ssh2` は最適化されたネイティブの暗号処理ではなく、Node.js だけで動く実装で動作します。**通常のローカル環境に `npm install` した場合と比べて、SFTP 通信がやや遅くなります。** これは意図的なトレードオフです。ネイティブモジュールをビルドすると macOS 専用のバイナリが生成されてしまい、この拡張は macOS と Windows の両方に対応すると宣言しているため、Windows の受講者には動かないファイルを配ってしまうことになります。加えて、以前の同梱方式ではビルドを行ったパソコンのホームディレクトリのパスが拡張ファイルの中に紛れ込んでいました。この2つの問題を避けるため、ネイティブビルドをそもそも行わない方式を採用しています。FTP・FTPS が中心の日本のレンタルサーバー環境では、この速度差は実用上ほとんど気になりません。

## 3. 本番反映の「合言葉」

本番サーバーへの反映（push）には、チャレンジコード + 合言葉の確認が必要です。設定 UI の「合言葉」欄には、**FTP のパスワードとは別の文字列を入力してください。**

反映を求めると、AI から6文字のチャレンジコード（例: `A7K3PQ` のような形式）が提示されます。あなたはそのチャレンジコードと、あらかじめ設定した合言葉をつなげてチャットに入力し、反映を承認します。

### 既知の限界

この仕組みは「AI がひとりで本番反映を実行できないようにする」ためのものですが、**完全な防止ではありません。** 一度チャットに合言葉を入力すると、その文字列はその会話の中で AI から見える状態のまま残ります。**同じ会話の2回目以降の push では、AI が自力で新しいチャレンジコードと合言葉を組み合わせて、人間の入力なしに承認を完了させられる可能性があります。** つまりこのゲートが保証するのは、**そのセッションで最初に行われる push を必ず人間が承認する**ことだけです。この拡張が教える手順（本書「1. 導入手順」および AI 向けのセットアップ手順）では、その最初の push はテスト用サブディレクトリへの**練習 push**です。つまり合言葉は練習 push の時点で一度消費されるため、「本番反映そのものを人間が承認する」ことや「同じ会話内でのその後すべての push（本番反映を含む）を人間が検証した」ことまでは保証しません。

完全にこれを防ぐには MCP の elicitation（AI からは見えない形で人間に直接入力を求める仕組み）が必要ですが、Claude Desktop はこれを未実装です（Claude Code の一部の利用形態のみ対応）。そのため、この拡張では次の緩和策を組み合わせています。

- 合言葉を FTP のパスワードとは別の文字列にする（万一 AI の会話ログに残っても、サーバーへの侵入経路にはならない）。
- 合言葉が提示された事実と受理された事実を、毎回 `.aiftp/log.jsonl` に記録する（`confirm-phrase-challenge` / `confirm-phrase-accepted`）。
- Claude Desktop 自体のツール承認ダイアログを、二重目のゲートとして残す。

このゲートが実際に守っているのは `aiftp_push_confirm` による本番反映だけです。**ロールバック（`aiftp_rollback`）とバックアップからの復元は、この合言葉ゲートの対象外です。** 両者の実際の書き込み範囲は異なります。ロールバックはリモートサーバーへの書き込み（1つ前の状態の再アップロード）を行いますが、バックアップからの復元はプロジェクトフォルダ内へのローカルファイル書き込みのみで、リモートサーバーへは一切書き込みません。合言葉ゲートの対象外である点は変わりませんので、その点を理解した上でお使いください。

## 4. 合言葉を設定しない場合

合言葉欄を空のままにしたときの挙動は、**Claude Desktop 拡張から使うか、ターミナルや Claude Code から MCP サーバーを直接使うかで異なります。** 同じ「未設定」でも結果は正反対なので、必ず両方を区別してください。

- **ターミナル / Claude Code から使う場合**: 合言葉が未設定でも、v0.12 と同じ `acknowledge_production` のみのゲート（合言葉なしで、明示的なフラグの確認だけで反映が進む挙動）のままです。これは CLI 版の既存利用者との互換性を保つための、意図した挙動です。
- **Claude Desktop 拡張から使う場合**: 設定 UI の「合言葉」欄を空のままにすると、本番反映は `acknowledge_production` だけでは進まず、**エラーで拒否されて止まります。** v0.12 挙動へのフォールバックはありません。**研修では、合言葉は必ず設定してください。**

## 5. トラブルシューティング

拡張の設定が揃っているかどうかは `aiftp_setup_status` ツールで確認できます。次の6項目それぞれについて `pass` / `fail` を報告します。エラーの識別子（`bootstrap` など）は英語のままですが、対処方法は `hint` に日本語で表示されます。

| チェック id | 内容 |
|---|---|
| `bootstrap` | 拡張の初期設定（`.aiftp.toml` 生成・キーチェーン保存・サイト台帳登録）が一通り完了しているか |
| `project_dir` | 設定したサイトフォルダに実際にアクセスできるか |
| `config_file` | `.aiftp.toml` が作成済み・または既存で読み込めているか |
| `credential` | パスワードが OS のキーチェーンに保存されているか |
| `registry` | サイトがサイト台帳に登録されているか |
| `confirm_phrase` | 本番反映用の合言葉が設定されているか |

`fail` になっている項目があれば、`hint` の指示に従って **Claude Desktop の設定 → 拡張機能 → aiftp** で該当欄を入力し、**Claude Desktop を再起動してください。** 設定が不足していても拡張自体は必ず起動するように作られています（起動そのものを失敗させると、Claude Desktop 側は「接続エラー」としか表示できず、何が悪いのか分からなくなるためです)。

## 6. CLI 版との関係

Claude Desktop 拡張は、npm でインストールする CLI 版（`@aiftp-tools/cli`）と同じ設定ファイル（`.aiftp.toml`）・同じサイト台帳・同じ OS キーチェーンを共有します。どちらか一方で `init` したフォルダは、もう一方からもそのまま使えます。
